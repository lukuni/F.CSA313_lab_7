## Хэсэг E — Дүгнэлт (debrief)

Хамгийн үр дүнтэй нь Supermodel аялал байсан: эхний дэлгэцийг товч дарахгүйгээр спецификацитай харьцуулахад л 3 согог (BUG-01 таслалтай он, BUG-02 ногоон «Устгах», BUG-03 тоолуур +1) олдож, «Хуучин хувилбар» линк дээр дарахад BUG-04 (500 алдаа) гарсан. Couch Potato аялал хоосон маягтаар BUG-05-ыг, Obsessive-Compulsive аялал нэг номыг давтан нэмэх, устгахад BUG-06 (давхардал), BUG-10 (буруу мессеж)-ыг олж, BUG-03 нь ямар ч төлөвт +1 байдгийг баталсан. Saboteur аялал curl-аар буруу JSON илгээхэд 200 OK буцаж буйг (BUG-07) илрүүлсэн бөгөөд charter-т тусгасан хил утгууд (99, 2209, «jog») BUG-09-ийг, том/жижиг үсгийн хайлт BUG-08-ыг гаргасан. Charter-аас гадуур санамсаргүй олдсон зүйл нь 300 тэмдэгттэй гарчиг анхааруулгагүйгээр 37 тэмдэгт болж хадгалагдсан явдал (BUG-11?) болон нэмсний дараа маягт цэвэрлэгдэхгүй байсан ажиглалт юм. Шалгагдаагүй үлдсэн зүйл: зөвхөн нэг талбар хоосон байх тохиолдол, тусгай тэмдэгт (`<script>`, emoji), зохиолчоор хайх, API-д хоосон бие эсвэл талбар дутуу хүсэлт, текстийн үсгийн алдааг бүх мессежид нарийвчлан шалгах — эдгээр нь дараагийн session-ий charter болно. Лаб 1-ийн Playwright автомат тест урьдчилан бичсэн assertion-тай бол BUG-01 (текст «1999» эсэх), BUG-03 (мөрийн тоо = тоолуур), BUG-04 (хуудасны статус), BUG-05, 06, 08, 09, 10 (мөр нэмэгдсэн эсэх, мессежийн текст)-ыг, мөн API request-ээр BUG-07-г барих боломжтой. Харин BUG-02 (товчны өнгө), урт текстийн харагдах байдал, «сонин» санагдах зүйлс нь CSS өнгийг тусгайлан шалгаагүй бол зөвхөн хүний нүдээр олдоно. Хамгийн гол ялгаа нь автомат тест зөвхөн бидний урьдчилан таамагласан зүйлийг шалгадаг бол exploratory session-д 500 алдаатай линк, өгөгдөл тасрах зэрэг хэн ч тест бичихээр төлөвлөөгүй согог олдсон явдал юм.
